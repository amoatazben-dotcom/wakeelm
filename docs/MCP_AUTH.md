# MCP authentication

Unauthenticated public servers and per-user bearer tokens are supported. Token messages are best-effort deleted in private chat and encrypted in server configuration. OAuth credentials are separately encrypted and keyed to application user + MCP server + issuer, with explicit scopes and expiry. Removing the server clears both forms. Tokens never enter model context or Git configuration.

OAuth discovers resource metadata at the server origin's `/.well-known/oauth-protected-resource` plus the MCP path, then authorization-server metadata. Exactly one HTTPS issuer is required, returned issuer/resource identities must match, S256 must be advertised, and auth/token endpoints must share the issuer origin. Configure a previously registered public client in `MCP_OAUTH_CLIENTS={"https://issuer.example":"client-id"}`. Automatic dynamic registration and confidential-client secrets are not supported.

The user explicitly enters scopes; they must be advertised by the resource/issuer. A private ticket binds the user/server/current URL and short expiry. Opening the ticket consumes it and issues random state, PKCE verifier/challenge and a secure HttpOnly nonce cookie. Callback `/integrations/mcp/oauth/callback` consumes SQL state atomically once, checks cookie/kind/user/current URL/issuer (including `iss` when required), and sends the original redirect and resource indicator. Wrong nonce/expiry/replay cannot exchange a code.

The token response must be Bearer with bounded lifetime and scopes no broader than the user's request. Access and refresh values are encrypted. Expiry causes a Redis-locked refresh with the same issuer, endpoint, client, server/resource and granted scopes. Rotated refresh tokens replace the encrypted value; refresh failure does not widen scopes or fall back to a global token. The user reconnects after revocation/failure. A narrower grant cannot authorize a tool requiring additional scopes.

The UI's OAuth action asks for explicit new scopes; the application never silently expands them. Unknown issuers have no client and fail closed. Authorization metadata using cross-origin endpoints, multiple issuers, alternative discovery layouts or registration requirements outside this explicit profile needs a reviewed future adapter. The callback base must be an operator-controlled HTTPS domain; register that exact callback in the issuer.

API access logs are disabled by start.sh because URLs contain state/code/tickets. Reverse proxy and external observability must also avoid query logging. State payloads are encrypted; only the SHA256 of state/nonce is stored for validation. Controlled tests verify PKCE, redirects, issuer checks, nonce, replay, expiry, encryption/isolation, refresh failure and returned-scope escalation.

MCP_CALLBACK_BASE_URL is a supported alias for INTEGRATIONS_CALLBACK_BASE_URL. After explicit authorization the user may resume the same failed auth job/step; existing deadlines and policy checks remain in effect. Auth failures are safely audited.
